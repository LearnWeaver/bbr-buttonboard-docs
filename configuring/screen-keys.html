Screen keys and legends#

A screen key has a colour display inside the cap, so its legend can change: the same key can say INTAKE in one part of a match and CLIMB in another.

The protocol, the config app and the tile firmware all support screen keys, but the board has never been manufactured, and nothing on this page has run on real hardware. Everything here describes the design and works against the config app’s built-in fake board.

The two display tiles#

Tile Panel Keys
disp1 128 × 32 monochrome, 21 columns × 4 rows of text none — it is a readout, not a control
screenkey1 128 × 128 colour, inside a key cap 1

disp1 shows readouts: match time, a mechanism state, a message from the robot. screenkey1 is one key whose cap is the screen.

Both are ordinary tiles: they go anywhere on the chain and are addressed like any other.

Showing text and pictures#

A display tile shows text in a grid of characters, drawn in the tile’s own font.

There are two ways to show a picture:

Stream it Store it in a slot
Colours Two, dithered Full colour
Time to show ~0.2 s, every time A few milliseconds
Time to load none a few seconds, once
Kept where nowhere; the panel holds it until cleared the tile’s own flash chip

Stream a picture you show once. Store the pictures you use as legends.

A screenkey1 has room for several stored pictures. Each numbered place is a slot.

Loading a picture into a slot#

In the config app’s Configure screen, select the tile and find the Picture section of the inspector.

  1. Choose an image file. The app shows you what the tile will actually draw — re-sized and encoded for that panel — not the file you picked.
  2. Set send as to a stored picture.
  3. Choose the slot and, on a colour panel, the encoding. Full colour is rgb565; the one-bit form is smaller and faster to load.
  4. Press Store in slot n.

The slot is erased when the transfer starts and holds a picture again only once the whole transfer has arrived and its checksum matches. An interrupted store leaves the slot empty, never half-drawn. If it fails, the app says so; store it again.

The Slots section lists what is in each one, with Show and Erase buttons.

What a slot holds cannot be read back — there is no command that asks. The list in the config app is what that page put there, not what the tile reports. Close the tab and it forgets; the pictures stay on the tile.

Binding legend codes#

A stored picture is switched by a number, and that number is what robot code sends. A code names an entry in a map, which says which tile and which slot, so the panel layout or the pictures can change without changing robot code. The Legend codes section of the same inspector binds them.

There are fifteen codes, 1 to 15. Each row picks a slot on this tile:

Code Bound to
1 slot 0 — intake.png
2 slot 3 — climb.png
3 unbound

A code with no binding does nothing, and so does a binding whose tile is unplugged or whose slot is empty. No error is shown.

Zero is never a legend. Zero stops a rumble and leaves every screen unchanged.

Bindings are part of your saved configuration, so press Save when you are happy with them.

Getting them there from a terminal#

Everything above is also a command on the serial channel:

python3 tools/bbctl.py --rumble-list              # what is bound now
python3 tools/bbctl.py --rumble-bind 3 5 0        # code 3 → tile 5, slot 0

Loading a picture is disp <addr> slot <n> begin/data/end, which tools/bb wraps.
