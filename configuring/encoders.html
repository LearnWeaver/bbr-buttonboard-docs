Rotary encoders#

The enc2 tile carries two rotary encoders, each with a push-to-click shaft. They are the right control for anything continuous — arm setpoint, shooter speed, LED brightness on the robot — where a button can only step.

Encoder tiles are the newest part of the system. The protocol and the config app support them; the tile firmware is still in development. Everything on this page describes the design, not something you can plug in today.

What the Driver Station sees#

FRC. Each encoder can be bound to one of four axes. The axis reports an accumulated position — turn it clockwise and the number goes up, keep turning and it keeps going. Four axes is the whole board, so two enc2 tiles claim all of them.

An axis is not a joystick. It does not spring back to centre and it has no deadzone, because there is nothing to return to: the value is where the knob has got to.

FTC. XInput’s sticks are sprung and deadzoned, which throws away an accumulated position entirely. So under xinput an encoder becomes pulsed buttons instead: one button pulses per detent clockwise, another per detent anticlockwise, and your OpMode counts them.

Pulsed buttons are available under frc too, if you would rather count clicks than read a position.

The shaft push#

The push switch on each encoder is an ordinary key. Bind it like any other key — it takes a logical button number and behaves exactly as a keypad key does.

Zeroing#

An accumulated position needs a defined starting point. The board can zero any axis, or all of them, on command — at the start of a match, or when the mechanism it drives is homed.
