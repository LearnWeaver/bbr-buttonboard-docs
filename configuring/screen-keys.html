Screen keys and legends#

Most keys have a legend printed on the cap, and changing it means pulling the cap off. A screen key has a colour display inside the cap, so the legend is software — the same physical key can say INTAKE in one part of a match and CLIMB in another.

Screen keys are the newest part of the system, and further from your hands than the encoder tiles are. The protocol, the config app and the tile firmware all support them; the board has never been manufactured, and nothing on this page has run on real hardware. Everything here describes the design and works against the config app’s built-in fake board.

The two display tiles#

Tile Panel Keys
disp1 128 × 32 monochrome, 21 columns × 4 rows of text none — it is a readout, not a control
screenkey1 128 × 128 colour, inside a key cap 1

disp1 is the panel you put on the panel: match time, a mechanism state, a message from the robot. screenkey1 is one key whose cap is the screen.

Both are ordinary tiles on the same chain, in any order, and both are addressed like any other.

Text is cheap, pictures are not#

A display tile holds a grid of characters, not a picture. The board sends text and the tile draws it with its own font. That is what keeps a screen tile affordable in bus time — a line of text is a few dozen bytes.

A picture is a different matter. A 128 × 128 full-colour image is 32 KB, which is a couple of seconds of bus with everything else waiting. So there are two ways to put one on a panel, and choosing between them is the whole of this page:

Stream it Store it in a slot
Colours Two, dithered Full colour
Cost to show ~0.2 s of bus, every time One frame — a few milliseconds
Cost to load none seconds, once
Kept where nowhere; the panel holds it until cleared the tile’s own flash chip

Streaming is right for something you show once. Storing is what makes a legend work, and it is the reason a screen key can be in colour at all: the picture only has to cross the bus at configuration time, so the bus objection to 16-bit colour disappears. After that, changing legends is as cheap as changing a light.

A screenkey1 has room for several stored pictures. Each numbered place is a slot.

Loading a picture into a slot#

In the config app’s Configure screen, select the tile and find the Picture section of the inspector.

  1. Choose an image file. The app shows you what the tile will actually draw — re-sized and encoded for that panel — not the file you picked.
  2. Set send as to a stored picture.
  3. Choose the slot and, on a colour panel, the encoding. Full colour is rgb565; the one-bit form is smaller and faster to load.
  4. Press Store in slot n.

The slot is erased the moment the transfer starts and is not a picture again until the whole thing arrives and its checksum matches. So an interrupted store leaves the slot empty, never half-drawn. If it fails, the app says so and you store it again.

The Slots section lists what is in each one, with Show and Erase buttons for checking your work.

What a slot holds cannot be read back — there is no command that asks. The list in the config app is what that page put there, not what the tile reports. Close the tab and it forgets; the pictures stay on the tile.

Binding legend codes#

A stored picture is switched by a number, and that number is what robot code sends. The Legend codes section of the same inspector binds them.

There are fifteen codes, 1 to 15. Each row picks a slot on this tile:

Code Bound to
1 slot 0 — intake.png
2 slot 3 — climb.png
3 unbound

A code with no binding does nothing. So does a binding whose tile is unplugged or whose slot is empty — a match is not the place to pop up a configuration error.

Zero is never a legend. Zero is how the robot stops a rumble, and stopping a rumble must not change what is on a screen.

Bindings are part of your saved configuration, so press Save when you are happy with them.

Why the indirection is worth it#

A code does not name a key and it does not name a picture. It names an entry in the map, which says which tile and which slot.

That means the layout can change without the robot code changing. Move the legend to a different key, swap the picture for a better one, rearrange the panel between matches — the OpMode still says “show code 3”, and code 3 is whatever you have most recently decided it means.

Getting them there from a terminal#

Everything above is also a command on the serial channel, if you would rather script it:

python3 tools/bbctl.py --rumble-list              # what is bound now
python3 tools/bbctl.py --rumble-bind 3 5 0        # code 3 → tile 5, slot 0

Loading a picture is disp <addr> slot <n> begin/data/end, which tools/bb wraps.
