Binding buttons#

Keys, buttons, and why they are different#

A key is a physical thing on a tile. Keys are numbered from 0 within their tile, and a key on its own does nothing.

A logical button is what the Driver Station sees. There are 32 of them, numbered 1 to 32, and they exist whether or not anything is bound to them.

Binding connects the two. Until a key is bound, pressing it registers nowhere.

This indirection is the whole point. Your robot code refers to Button 7, and stays true when Button 7 moves to a different key, a different tile, or a different kind of tile entirely.

Binding a key#

In Configure, click the key, choose a button number, and press the key to confirm. The board waits for the press itself, so there is no way to bind the wrong key by mistyping a number.

Rebinding a key to a different button replaces the old binding, including any combo the key was part of.

Groups: several keys, one button#

Several keys can feed the same button. The button is pressed while any of them is down.

This is what you want for:

  • The same action reachable from two ends of a wide panel.
  • A driver and a co-driver who each need the same override.
  • An arcade button and a keypad key that do the same job.

Add a key to an existing button rather than replacing it, and up to 16 keys can share one button.

Combos: one key, several buttons#

The reverse works too. One key can press several buttons at once, and releasing it releases them all together.

The case that needs it is FTC. The Driver Station assigns a pad to gamepad 1 when it sees Start+A, and to gamepad 2 on Start+B. That normally takes two hands. Bind one key to each and it takes one press.

In Configure, click the key, then:

  • Start+A or Start+B sets that combo in one click.
  • Combo turns on toggling: each number you click is added to the key, or taken off it. Click Combo again to go back to picking one button.

The key shows every button it feeds, for example B1+8. A combo does not take the buttons away from other keys: a key bound to Start+A and a separate key bound to Start both work.

If the buttons in a combo have different LED colours, the key shows the colour of the lowest-numbered one.

The Driver Station sees every button in a combo change in the same instant. It does not see Start first and then A. The board sends the combo correctly, but whether the Driver Hub accepts simultaneous presses has not been tested on one yet. If it does not, bind Start and A to two separate keys as before.

Debounce#

Mechanical switches make and break contact several times in the few milliseconds around a press. The tile filters that out, and the default — 5 ms — suits every switch these tiles are designed for.

You can raise it per tile if a particular switch chatters, at the cost of that much latency on every press. Worn arcade microswitches are the usual reason.

What happens when a tile disappears#

If a tile stops answering — cable pulled, board damaged — every button bound to it reads as released, immediately. Not “stuck at whatever it was last”, which is the failure mode that drives a robot into a wall.

Bindings to a missing tile are kept, not deleted, so unplugging a tile to work on the panel and plugging it back in costs you nothing.

Swapping and replacing tiles#

Bindings are stored against a tile’s position on the bus, and the board remembers which physical tile was in each position.

  • Replace a broken tile with an identical one — the new tile takes the old one’s place and its bindings, automatically.
  • Add another tile of the same kind — it is a new tile, and starts unbound.

When the board cannot tell those two cases apart, it says so instead of guessing, and the config app offers the choice. Nothing is silently rebound.

Saving#

Bindings work as soon as they are made, but live in RAM until you press Save. Save writes them to flash and reads them back to check.
